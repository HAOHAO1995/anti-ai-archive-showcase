# Roadmap / 路线图

## Infrastructure branch / 基础设施分支

Public source, frozen versioned exports, evidence references, separate counting, bilingual download/citation page, rights boundary, integrity tests and CI. Acceptance requires a clean independent install/build and passing checks, followed by review of the concrete GitHub changes.

公开源码、版本化导出、证据引用、独立统计、双语下载引用页、许可边界、测试与 CI；验收须完成独立安装构建、检查并审阅 GitHub 具体改动。

## Next research release / 下一次研究发布

Review pending fact checks and translations by priority; investigate source-date conflicts and shared-source duplicate candidates; verify broader link availability; reconcile approved new research separately from this frozen snapshot. Retain correction history. No automated claim of exhaustive coverage.

按优先级人工审阅事实与翻译；追踪日期冲突与共享来源的疑似重复；扩大外链核查；新研究与固定快照分开验收，保留更正历史，不自动宣称穷尽。

## Preservation and collaboration / 保存与协作

Create a tagged, checksum-verified GitHub release after acceptance. Consider a DOI deposit only after confirming repository ownership, rights and release metadata. Add contributor review and attribution records; expand accessible browser/device coverage and obtain redistribution permissions where worthwhile. None of these future milestones is represented as already achieved.

验收后建立标签与校验和完整的正式版本；确认所有权、权利及元数据后再考虑 DOI 存储。补充贡献审核署名、浏览器与设备无障碍覆盖，并按需申请媒体转载许可。这些未来事项均不视为已完成。
